# HTTP contract

Interactive OpenAPI is served at `GET /docs/` and `GET /docs/json`.

## Canonical v2 publish API

```text
POST /v2/pass-uploads
POST /v2/pass-uploads/token
POST /v2/pass-uploads/:uploadId/finalize
```

`POST /v2/pass-uploads` and finalization require an allowed browser `Origin` and
an empty body. The upload-authorization endpoint accepts the JSON protocol
generated by `uploadPresigned` from `@vercel/blob/client`; callers must not
invent that body manually. Its rules are PNG-only, one deterministic pathname,
8 MiB maximum, 15-minute validity, multipart enabled, and no overwrite.

The flattened image contract is:

| Field | Required value |
| --- | --- |
| Template | `builder-pass-v2`, version `2` |
| MIME | `image/png` |
| Dimensions | `1134x1926` |
| Input bytes | at most `8388608` |
| Pages | one, non-animated |

Finalize returns `201` for a new commit or `200` for an idempotent retry, with
the absolute public pass URL in `Location` and the `{ "pass": ... }` envelope
documented in `frontend-integration.md`.

## Public delivery

```text
GET|HEAD /pass/:shareId
GET|HEAD /pass/:shareId/card.png
GET|HEAD /pass/:shareId/og.jpg
```

The page returns crawler-ready HTML in the initial response. Its `og:image` and
`twitter:image` are direct immutable public Blob URLs. Card/OG artifact
routes return `307` to those same Blob URLs. Missing, malformed, expired, and
uncommitted IDs are indistinguishable `404` responses.

## Errors

Errors use `application/problem+json` with `code`, `status`, `detail`,
`requestId`, and `retryable`. Relevant v2 codes include:

| Code | Status | Retryable |
| --- | ---: | --- |
| `INVALID_REQUEST` | 400 | no |
| `UNAUTHORIZED` | 401 | no |
| `ORIGIN_NOT_ALLOWED` | 403 | no |
| `UPLOAD_NOT_READY` | 409 | yes |
| `PAYLOAD_TOO_LARGE` | 413 | no |
| `IMAGE_TYPE_MISMATCH` | 415 | no |
| `INVALID_IMAGE` | 422 | no |
| `INVALID_IMAGE_DIMENSIONS` | 422 | no |
| `ANIMATED_IMAGE_NOT_SUPPORTED` | 422 | no |
| `RATE_LIMITED` | 429 | yes |
| `IMAGE_PROCESSING_TIMEOUT` | 503 | yes |
| `SHARE_STORAGE_UNAVAILABLE` | 503 | yes |

There is no raw backend-upload alternate API. All clients use the v2
direct-to-Blob flow and the canonical `/pass/:shareId` routes.
